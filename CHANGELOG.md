# Changelog

## 0.5.0.dev3 — 1 November 2026

- Connect computed SearchReport evidence to complete HardwareReports with whole-input membership/identity/collision preflight and unchanged upstream verification budgets.
- Derive conservative interval fronts, selected-objective completeness, coverage diagnostics and immutable producer-only rows.
- Add strict hardware-report JSON v1. Replay nested source evidence, costs, freshness, work and fronts without numerical calls or current environment capture; retain recorded evidence and historical metadata.
- Add 28 tests to the preserved 232. Audit 1,116 actual assessments/replays across all 31 objective subsets, plus 13 abstract fronts and 900 interval pairs, using independent path/ledger/front/key oracles.

The public hardware assessment/report API is implemented. The hardware CLI and final 0.5 release gates remain pending; target profiles are synthetic and numerical snapshots/calibration metadata are not authenticated.

## 0.5.0.dev2 — 1 November 2026

- Implement the internal matrix-free native-support/work/timing kernel. Preflight the entire batch, enforce exact dimensions and ordered edges/bindings, retain every rejection and charge whole operation counts with later-small-after-skip behaviour.
- Derive exact integer critical-path/serial ranges with a per-site fold and explicit-instant freshness. Preserve unknown/stale timing, identity zero time and used-error definitions/counts without deriving circuit fidelity.
- Add 26 tests to the preserved 206, covering maximum domains/ticks, complete rejection evidence, budgets, timing, preflight and allocation-free behaviour.
- Add an independent production audit of 3,110 timing circuits, 2,752 gate-availability circuits and 5,000 budget ledgers plus every frozen target/timing/freshness/ledger case. Require it in numerical CI and both clean wheel/source installations.

This completes the internal arithmetic work package. Its private status flags are not public verification evidence. The complete fresh-source report producer, interval fronts, strict recorded replay and hardware CLI remain pending. The original benchmark fixture, source semantics and stable tags are preserved.

## 0.5.0.dev1 — 1 November 2026

- Implement strict input JSON v1, canonical content/placement identifiers, relative timestamp and placement-arity helpers. Preserve exact integer ticks and gate-error definitions; reject malformed fields, Unicode, numeric values, ordering and wire overflow.

This development stage completes input models and the external composition baseline. Hardware feasibility/cost assessment, HardwareReport/replay and hardware CLI remain pending. Stable v0.3.0/v0.4.0 tags and interpreter/verifier semantics are preserved.

## 0.3.0 — 1 November 2026

- Adopt ADR 0001: verify explicit logical-to-physical encoding before candidate search or optimisation.
- Add `LogicalProgram` and `BasisEncoding`, strict canonical JSON v1, stable diagnostics and distinct model/wire/allocation budgets.
- Add linear arbitrary-state application while retaining the original zero-input simulator and shared gate application code.
- Verify complete small operators under one global phase with Frobenius subspace, leakage and unitarity criteria; distinguish pass, fail and unsupported requests.
- Add validated reference matrices labelled reference-only, a `q3hash-verify` CLI and a three-gate two-qubit implementation of logical qutrit shift.
- Add normative and adversarial tests, independent NumPy/SciPy operator checks, and installed-distribution verification of both CLI entry points.

The original source grammar and logical gate semantics are preserved. Candidate search, optimisation, hardware synthesis and report wire serialization are deferred. Numerical evidence is not formal proof or hardware execution.
