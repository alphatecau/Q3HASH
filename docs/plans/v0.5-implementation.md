# v0.5 implementation sequence

**Status:** v0.5.0.dev1 completes input models/serialization and the independent
Cirq composition baseline. Cost assessment, HardwareReport/replay, hardware CLI
and a device-data adapter remain pending. Stable 0.3.0/0.4.0 tags are preserved.
**Date:** 1 November 2026, Australia/Brisbane.
**Contract:** [Hardware profile and conditional cost v1](../contracts/hardware-profile-v1.md).

## Intended outcome and deciding assumptions

For the same verified logical workload, explain which explicitly placed supplied
circuits a declared target model supports, which data is missing, and which cost
trade-offs follow under that model. Preserve the v0.4 search domain and evidence.
Prefer a useful bounded assessment over invented routing, error aggregation or
universal rankings.

The first model supports existing IR gates only when the profile explicitly gives
their ordered-site implementations. No automatic native-gate decomposition is
assumed. Durations use exact integer picosecond ranges; calibration freshness uses
an explicit as-of instant. Per-gate error records remain diagnostic because the
first contract has no noise-composition model. Comparisons share one profile and
use separated interval endpoints, retaining uncertainty overlap and ties.

Synthetic profiles are test scenarios. Their numbers are not measured calibration,
a device recommendation or a published performance benchmark.

## Frozen workloads and current evidence

The [fixture](../../benchmarks/hardware-cost-v1.json) supplies full sources,
encodings and expected operator outcomes for:

| Workload | Supplied implementations | Current acceptance |
| --- | --- | --- |
| Qutrit shift | Native qutrit, three-gate two-qubit circuit, cyclic native seed | All pass the existing complete-subspace verifier; compare actual gates and explicit mappings. |
| Qutrit entangling | Native Fourier plus SUM; reordered physical qutrit axes | Full nine-state operators agree under the explicit transpose map. A binary implementation is not supplied and remains unimplemented. |
| Mixed entangling `(2,3)` | Native axes and reordered `(3,2)` circuit | Full six-state operators agree under the explicit basis reorder. |
| Adversarial controls | Leaking four-state shift, qubit relative phase, dense-limit request | Fail/fail/unsupported as specified; never receive hardware-front eligibility. |

In particular, do not wrap an embedded Fourier matrix in a generic matrix gate and
count it as a synthesised native binary implementation. An external numerical
reference can check that matrix's semantics without establishing hardware feasibility.

`tools/check_hardware_contract.py` now checks these cases with the existing public
verifier and a small reference model for site/gate checks, exact path timing,
freshness, bounded work and interval fronts. It lives outside `src/q3hash`, uses
only tiny declared fixtures and is not the proposed production implementation.
Its path enumeration is intentionally different from the planned per-site timing
algorithm. The validation document records the actual case counts.

## Independent framework baseline specification

Use Cirq's explicit dimensioned Qids and `qid_shape`, with a recorded supported
version installed only in validation tooling. Pass the exact register order to
`Circuit.unitary`; include spectator sites and use complex128. Do not rely on
default lexicographic name order or ignore terminal measurements implicitly.
These workloads are unitary and contain no measurement.

Construct local gate matrices independently from the published mathematical rules
and explicit tensor labels, without importing Q3# gate, stride or operator helpers.
Cirq composes those local gates into full operators. For the binary circuit, also
use built-in X/CNOT where appropriate. Report that custom qudit matrices validate
composition, not native device availability. Compare every operator column and
several unnormalised complex inputs, preserve one shared phase, and exercise
non-adjacent/reversed axes. Existing NumPy/SciPy audits remain unchanged.

Reference software absence is an error; an optional missing library is not a
pass. The dedicated external CI job actually runs the declared baseline.
Do not choose or claim a measured device-cost baseline until a reproducible target
snapshot and semantic gate mapping are available. Source/profile provenance and
framework version/settings belong in the evidence record.

## Complexity and budgets

Production profile validation is bounded by 64 sites, 4032 directed edges and
8192 bindings. Source reports contain at most 4096 candidates, and a circuit has
at most 16,384 operations under the v0.4 settings. A separate bounded gate-check
ledger prevents repeated hardware analysis from becoming unbounded.

The intended production timing pass is linear in operations and touched axes;
reference path enumeration is tiny-domain-only. Pareto comparison may be quadratic
in retained eligible rows within the existing 4096-row cap. No full hardware-state
product or channel matrix is allocated by cost analysis. Existing numerical work
is reused from fresh source evidence, not recharged or silently omitted.

## Release and regression criteria

The next package is matrix-free feasibility, deterministic work accounting and
critical-path ranges in `hardware_costs.py`. Keep its arithmetic separate from the
independent path oracle and from the numerical verifier.

- Keep all 186 v0.4 tests, seven source examples, the existing CLI/API behaviour and
  original numerical/search audits. Stable 0.3.0 and 0.4.0 tags must not move.
- Demonstrate all acceptance IDs in the contract against production models and
  against independent reference vectors; testing a reference oracle alone is not
  evidence of delivered production functionality.
- Exercise strict report tampering, unknown timing/error data, age boundaries,
  directed/mixed connectivity, unplaced/ineligible rows, interval overlap/ties,
  count-only objectives and resource-budget exact boundaries.
- Build/install clean wheel/source distributions across Python 3.10–3.13 and run
  the numerical/external baselines on the exact reviewed commit.
- Preserve research scope on the website. Full browser/Python execution integration
  remains the v0.6 milestone; this planning change does not deploy a new runtime.
