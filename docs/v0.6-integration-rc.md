## Benchmark evidence

The suite uses explicit mixed-radix maps in last-register-fastest order. The independent standard-library oracle builds every logical and physical matrix column and recomputes subspace residual, leakage, unitarity and structural resource counts. The JSON report binds the sources and fixtures by SHA-256. Reported metrics use 12 decimal places and classification uses the unrounded values.

| Workload | Result | Coverage |
| --- | --- | --- |
| Qubit shift | PASS | Native qubit, binary spectator and mixed spectator with gapped indices |
| Qutrit shift | PARTIAL | Native `(3)`, binary `(2,2)` and mixed `(2,3)` pass. The `(3,2)` circuit has no supplied implementation. |
| Active mixed SUM | PARTIAL | Both SUM directions act on the logical qubit and qutrit. Native, reversed `(3,2)` and nonzero-spectator maps pass. The all-binary candidate has no supplied circuit. |
| Negative controls | FAIL as expected | Wrong mixed-radix order and leakage into the unused qutrit embedding state |

The fixed qutrit comparison retains its synthetic timing model and partial Pareto front. The new workloads report structural resources. Their results do not measure hardware performance.

## Classification at the hosted boundary

| Classification | Evidence |
| --- | --- |
| PASS | Complete normalised statevector or every encoded-subspace metric within `1e-10` |
| FAIL | At least one evaluated verification metric exceeds tolerance |
| UNSUPPORTED | A valid request exceeds a declared size limit. In the offline suite, an unsupplied circuit has no numerical metrics or resources. |
| PARTIAL | The fixed benchmark retains three verified candidates and the explicit unimplemented row. The offline workloads retain any missing implementations in their reports. |

The hosted adapter refuses a worker status that contradicts its evidence and returns the existing worker-error response. Invalid requests still use the existing input-error contract. The separate Sites v2 relay independently validates the response before it can display a result.

## Reproduce

From a clean checkout, install the package and test dependencies described in the [deployment guide](../deployment/README.md), then run the following commands.

```sh
python -I -m unittest discover -s tests -v
python -I tools/check_encoding_integration.py --json
python -I tools/check_three_way_oracle.py
python -I tools/check_three_way_benchmark.py
python -I tools/check_hosted_api.py --commit "$(git rev-parse HEAD)" --validate-schema --output /tmp/q3hash-api.json
cd integration/sites
npm ci
npm run typecheck
npm run build
Q3_CONTRACT_FIXTURES=/tmp/q3hash-api.json npm test
```

The hosted acceptance cases check both orientations of unequal-dimensional SUM, signed amplitudes, gapped and reordered injections, wrong maps and exact dimension boundaries at 64/65 simulation states and 32/33 verification states. Loopback uses a temporary credential and exercises the real isolated Python worker.

## Release gates

Review the draft branch and its exact-commit CI. An approved staging deployment must select the reviewed candidate commit and pair the v2 Render candidate with a compatible staged Site relay. Follow the [staging and rollback procedure](../deployment/README.md) to verify authenticated Render TLS, Sites sign-in and logout, and desktop and Android browser behaviour before any production cutover. The working v12 Site and its v1 Render backend provide the rollback baseline.
